# Network A — Laptop A (standalone)

Generated by `scripts/export_standalone.py` in the combined repo. Do not edit by
hand; re-run the exporter to regenerate.

Network A tails its OAI CN5G AMF log + UPF Prometheus metrics, builds per-UE
behavioural summaries, and serves them on **:8001**. It has no reference to
Network B — the two cores only talk over HTTP (Network B pulls summaries from
this API).

## Run

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # fill in Postgres + HMAC_SECRET_KEY
uvicorn network_a.api.app:app --host 0.0.0.0 --port 8001
```

`HMAC_SECRET_KEY` MUST match Laptop B's, or the two cores won't agree on UE
identity — and won't be able to verify each other's request signatures.

## Signed summary channel

The cross-network link (`POST /v1/summary/request`) is HMAC-signed. Network A:

- **verifies** every inbound request — missing, tampered, expired (>5 min skew),
  replayed, or wrong-key signatures are rejected with **401**;
- **signs** its response body so Network B can confirm the summary really came
  from A.

The scheme (`network_a/contract/request_signer.py`, vendored byte-identical into
Network B) is HMAC-SHA256 over `version∥method∥path∥timestamp∥nonce∥sha256(body)`,
carried in `X-Sig-*` headers. Set `REQUIRE_SIGNED_REQUESTS=false` to disable
enforcement during a controlled rollout; the default is **on (fail-closed)**.

Network B's own `/v1/access/request` (same-trust-zone, localhost) is **not**
signed in v1 — see the follow-up note in Network B's README.
